## 1. 结论

旧 ranges 不合理的根因是语义混合：`base_need_vector` 原本用于表达五行对个人的相对重要程度，但旧算法把归一化后的数值直接当作理想城市构成。主喜因此被推到 28.4%–56.1%，强忌上限则经常只有约 5.8%–8.9%。这与现有 100 城的实际向量尺度不相容。

本轮把两个概念分开：

- `need_strength`：继续保存本命、调候和大运合成后的相对重要程度、五档标签、证据与置信度。它不等于城市应该含有多少该元素。
- `preferred_city_exposure`：基于当前 100 城中该元素的经验分布，描述城市暴露的低限、目标和高限。

推荐 **R2 平衡重叠方案**进入 Chat 审核。它让 15/15 人工案例和 2,985/3,000 组合成需求至少有一个城市让五项同时落入范围；100 城全部仍进入过 Top 10。主喜目标为 19.9%–33.8%，不再机械追求 40%–50%。该方案仍是候选，不改名为正式版本。

## 2. 语义和接口

### 2.1 `need_strength`

保留 `personal-need-v0.1-candidate` 的下列内容：

- `base_need_vector` 与 `current_need_vector`；
- 主喜、次喜、中性、忌、强忌五档；
- 命理证据轨道、主/辅助方案和置信度；
- 大运轻修正及其位移、排序保护。

`need_strength` 用于回答“这个元素对当前解释有多重要”。它不能独立回答“城市里该元素多少最合适”。

### 2.2 `preferred_city_exposure`

候选接口为：

```json
{
  "element": "water",
  "tier": "strong_prefer",
  "low": 0,
  "target": 0,
  "high": 0,
  "low_quantile": 0,
  "target_quantile": 0,
  "high_quantile": 0,
  "within_tier_need_position": 0,
  "source_city_version": "city-elements-v0.2.1-scheme-c-candidate",
  "range_version": "preferred-exposure-r2-balanced-candidate"
}
```

所有比例继续使用 `[木,火,土,金,水]` 固定顺序。`need_strength` 与 `preferred_city_exposure` 必须分别保存和版本化，前者变化不能被描述成城市构成的同等百分点变化。

## 3. 校准方法

设 100 城中元素 `i` 的经验分位函数为 `E_i(q)`。每个五档先定义分位区间 `[qL,qT,qU]`，再转换为：

`[L_i,T_i,U_i] = [E_i(qL+δ), E_i(qT+δ), E_i(qU+δ)]`

其中 `δ` 只保存同一档内部的连续差异：

1. 用原 3,000 组的 `current_need_vector`，分别计算每档的 Q10、中位数和 Q90；
2. 把当前元素在本档内的位置压到 `[-1,1]`；
3. R1 最多平移 4 个分位点，R2/R3 最多平移 5 个分位点；
4. 因为输入使用大运修正后的 `current_need_vector`，大运仍能轻度移动目标，但不再按城市百分点一比一传递。

这是现代产品校准，不是传统命理给出的数值规则。传统语义只支持喜、忌、调候和方位等高层含义。

## 4. 三套候选方案

表中数字是 `[下限分位 / 目标分位 / 上限分位]`。最终分位还会按档内 `need_strength` 小幅平移。

| 档位 | R1 选择性较强 | R2 平衡重叠 | R3 可行性优先 |
|---|---|---|---|
| 主喜 | 60 / 85 / 100 | 50 / 85 / 100 | 40 / 80 / 100 |
| 次喜 | 40 / 65 / 90 | 25 / 62 / 92 | 15 / 58 / 95 |
| 中性 | 20 / 50 / 80 | 10 / 50 / 90 | 0 / 50 / 100 |
| 忌 | 0 / 20 / 60 | 0 / 20 / 70 | 0 / 18 / 80 |
| 强忌 | 0 / 8 / 45 | 0 / 8 / 60 | 0 / 8 / 70 |
| 档内最大平移 | ±4 分位点 | ±5 分位点 | ±5 分位点 |

R1 保留较强选择性，但联合可行性仍不足。R3 能完全解决可行性，却让平均 28.6 城同时合格，区间过宽。R2 处于两者之间。

## 7. 大运、区分度与冻结边界

R2 继续读取原大运修正后的 `current_need_vector`，但只通过最多 ±5 个分位点的档内平移影响城市暴露：

- 3,000 组大运前后 Top 10 平均 Jaccard `0.925`，Top 1 改变 315/3,000；目标暴露平均移动 0.119 点，最大 2.597 点。
- 15 例大运前后 Top 10 平均 Jaccard `0.895`，Top 1 改变 2/15；目标暴露最大移动 0.983 点。

这与 T-005 的轻修正方向一致，没有把大运变成新的长期结构。R2 下同主喜、不同次喜或忌神的 Top 10 平均 Jaccard 为 `0.222`，略低于旧方案的 `0.232`，说明语义解耦没有牺牲用户间区分度。

本轮没有：

- 修改 `model_interval` 的强忌过量分母、幂次或权重；
- 重算 P5/P50/P95 娱乐指数；
- 修改方位 `±1.0` 同梯队规则；
- 修改任何命盘喜忌或城市向量；
- 进入 City Profile、前端或娱乐文案。

## 8. 推荐与下一步

建议 Chat 选择 **R2 `preferred-exposure-r2-balanced-candidate`** 作为下一轮强忌曲线校准的唯一 ranges 候选，但本轮不把它改称正式参数。

选择理由：

1. 解决 15/15 人工案例无全维可行城市的问题，并把合成集可行率提高到 99.5%；
2. 主喜目标保持在城市经验分布内，最大 33.8%，不会回到 40%–50% 的机械高目标；
3. 100 城全部进入过 Top 10，Top 5 HHI 和前十城占比均低于旧方案；
4. 比 R3 保留更强选择性和主喜区分度；
5. 强忌超限已从尺度性错误降为少量边界越界，适合下一轮单独校准过量曲线。

下一步只有在 Chat 批准 R2 后，才应固定 ranges 输入并校准强忌过量惩罚曲线。指数标定仍应留到曲线稳定之后。

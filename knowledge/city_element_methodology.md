## 1. 结论摘要

MVP 将每个城市表达为固定顺序的五维向量：

`[木, 火, 土, 金, 水]`

五项总和为 100，不给城市贴单一五行标签。2026-09-11 已按 Chat 固定的 100 城名单完成可复现事实快照、v0.1 基线与 v0.2 自然原型重算，详见 `data/cities.csv`：

- 100/100 城有唯一 GeoNames ID、坐标、时区和全部 11 个自然字段；所有自然字段 `missing=false`。
- 每个事实字段都附来源 ID、时期、单位、空间范围、许可、采集日、缺失状态和置信度；全部 100 个展示向量严格合计 100。
- 现代辅助四字段没有全球统一、可比且边界一致的数据，继续明确标为缺失；v0.2 不再用中性辅助响应稀释自然信号，而是把历史、大学、经济、行业、企业、美食和建筑保留给独立 `City Profile` 层。
- 事实层锁定为 `city-facts-2026-09-11-v1`，100 城校准样本锁定为 `cities100-2026-09-11-v1`。从 v0.1 到 v0.2 的事实子集哈希保持 `958EFA3C0D6852475543902EFB01E26A0618D1C6D8DC35EB6F87D33F120571B4`。
- `city-elements-v0.1.0` 与原始 `city-elements-v0.2.0-candidate` 均保留为逐城审计基线。Chat 已批准第 15 节方案 C；重算候选 `city-elements-v0.2.1-scheme-c-candidate` 的最高维度分布为木 26、火 11、土 4、金 26、水 33，成对 L1 平均为 37.982。
- 方案 C 没有城市名、地区或人工修分分支。它只改变四个原型响应，事实子集哈希、100 城原型权重和原型主导结果均保持不变；全部回归闸门通过，详见第 16 节。

当前模型结构为：

- 自然与地理环境层：100%，通过“事实 → 组合特征 → 原型权重 → 原型五行响应”计算。
- `City Profile`：独立解释层，不进入城市自然向量；未来只用于五行相近城市的事实差异化说明。
- 用户相对方位：不写入城市固有向量，只在最终匹配指数上作最多 `±3` 分的可选修正。
- 现实偏好：天气偏好、预算、签证、语言、职业机会等独立筛选，不进入命理匹配指数。

传统文献只提供五行的高层语义方向；“某毫米降水对应多少水”“金融占多少金”等具体量化关系没有传统金标，均属于现代产品设计。本方案因此要求事实、映射、评分和文案四层分离并分别版本化。

## 2. 设计边界与引擎接口

### 2.1 四层分离

1. **城市事实层**：保存数值、空间范围、年份、发布者、URL、许可和采集日期。
2. **五行映射层**：把事实字段映射为五维响应向量；保存规则版本、理由、反例和测试。
3. **匹配层**：使用个人需要向量、城市向量及轻度大运调整计算娱乐型指数。
4. **现实筛选层**：预算、签证、语言、天气偏好和职业等；独立展示，不改变命理分。

### 2.2 BaZi Engine → City Engine

City Engine 不读取生辰，也不反向修改命理结论。BaZi Engine 应提供：

```json
{
  "element_order": ["wood", "fire", "earth", "metal", "water"],
  "base_need_vector": [0, 0, 0, 0, 0],
  "primary_element": "",
  "secondary_element": "",
  "confidence": "high|medium|low",
  "dayun_adjustment_vector": [0, 0, 0, 0, 0],
  "rule_version": ""
}
```

`dayun_adjustment_vector` 的每项范围为 `[-1, 1]`，表示当前大运对“个人需要”的有利或不利方向。City Engine 不得仅凭大运地支所属五行自行判断吉凶。

## 3. 空间、时间与来源标准

### 3.1 城市空间定义

- 城市锚点使用 GeoNames 的 WGS84 坐标与唯一 ID；保存数据快照日期和许可信息。GeoNames 数据以 CC BY 4.0 提供。[^9]
- 自然环境默认统计锚点周围 **30 km 半径**，以减少行政边界差异造成的不可比性。
- 明确依赖行政区的现代城市功能字段，必须同时保存行政边界版本；不得与 30 km 自然环境统计混称为同一地理范围。
- 沿海距离、河湖邻近度和城市地表水比例是三个不同字段，不能互相替代。

### 3.2 时间基准

- 气候正常值统一使用 **1991–2020** 三十年窗口。
- 生产版优先从 ERA5/ERA5-Land 的温度、降水、辐射、湿度及蒸散相关变量计算一致窗口的指标。ERA5-Land 月平均数据覆盖 1950 年至今、约 0.1° 网格，并采用 CC BY 4.0。[^4]
- 本次 100 城可复现快照使用 NASA POWER Climatology API v2.9.7 的 1991–2020 点位气候值，参数为 `T2M`、`ALLSKY_SFC_SW_DWN`、`PRECTOTCORR`、`RH2M` 和月均温差。该服务支持自定义气候窗口和多参数请求。[^3]
- NASA POWER 气象输入来自 MERRA-2，原始气象网格约 `0.5° × 0.625°`；太阳辐射约 `1° × 1°`。因此气候字段记录为“GeoNames 锚点所在源网格”，不是 30 km 像元平均；本快照的总体数据置信度统一为 Medium。ERA5/ERA5-Land 仍是发布前可选升级项，但不是本次快照的实际来源。
- 地表覆盖默认使用 ESA WorldCover 2021 v200；其为 10 m、11 类全球地表覆盖产品，许可为 CC BY 4.0。[^5]
- 本快照从 WorldCover 2021 v200 云优化 GeoTIFF 的约 80 m overview 读取，以 1 km 系统网格统计 30 km 半径内植被和内陆地表水比例。海洋像元由 Natural Earth ocean polygons 剔除，避免“海洋面积”与“沿海距离”重复计权。
- 地形实际使用 Copernicus DEM GLO-90 2021 公开快照的约 180 m overview，以同一 1 km 网格统计陆地中位海拔及 `P90−P10` 起伏；海岸距离实际使用 Natural Earth 1:10m coastline。[^6][^7]
- HydroSHEDS/HydroLAKES 本轮未下载进数值链：HydroLAKES 全球包约 820 MB，且 WorldCover 已给出同尺度地表水覆盖。本轮没有把“首选来源栈”伪装成“实际已使用来源”。[^8]

### 3.3 来源优先级

1. 官方或国际科学数据产品，且方法、版本、许可清楚。
2. 城市/国家统计部门的可比指标。
3. 可复核的开放数据集。
4. 编辑策展只可用于文案，不得伪装成城市事实或在无标记情况下进入数值模型。

### 4.1 防止重复计权

- `precipitation`、`humidity`、`aridity` 都描述水分，但反映降水输入、空气状态和水分收支，必须分别保留并设置组权重上限；三项合计固定为 22，不再加入同义“湿润度”。
- `surface_water_fraction`、`coast_proximity` 与 `continentality` 分别描述本地水体、海岸邻近和气候海洋性，不互相复制。
- `elevation` 和 `ruggedness` 分别描述高度与起伏；平坦高原和低海拔山地应能得到不同结果。

## 5. 传统语义与现代映射的边界

《尚书·洪范》以“水曰润下、火曰炎上、木曰曲直、金曰从革、土爰稼穑”概括五行性质。[^1] 《黄帝内经·素问》进一步建立东方/风/木、南方/热/火，以及寒、暑、燥、湿、风等对应关系。[^2]

本产品只把这些内容作为高层语义锚点：

| 元素 | 传统语义锚点 | 在城市模型中的谨慎转译 |
|---|---|---|
| 木 | 生长、曲直、东方、风 | 植被、生长条件、教育与创新的辅助含义 |
| 火 | 炎热、向上、南方、明亮 | 温度、太阳辐射；活动性只在辅助层体现 |
| 土 | 稼穑、承载、中央、湿土 | 地形、海拔、地表稳定性；不是“所有陆地” |
| 金 | 从革、收敛、西方、燥 | 干燥、强大陆性；金融/制造是现代辅助类比 |
| 水 | 润下、寒、北方 | 水体、湿润、海洋性、低日照/低温倾向 |

以下内容明确属于**现代原创产品设计**，不是传统文献直接给出的结论：字段选择、30 km 半径、1991–2020 窗口、所有权重、百分位阈值、五维响应向量、余弦匹配、置信度收缩、大运 10% 上限和相对方位 `±3` 分。

## 6. v0.1 字段到五行响应矩阵（历史基线）

每个事实字段先转成 `q∈[0,1]`，再在低/中/高三个锚点间线性插值。每个锚点自身均按 `[木, 火, 土, 金, 水]` 排列且总和为 100。

| 字段 | 低值响应 | 中值响应 | 高值响应 | 设计理由与防偏差说明 |
|---|---|---|---|---|
| 温度 | `[10,5,15,20,50]` | `[30,20,25,10,15]` | `[20,50,10,5,15]` | 冷偏水、热偏火；中温给生长之木，避免冷热二分法 |

## 8. 归一化、取整与缺失值

### 8.1 字段归一化

对方向为“数值越大，q 越大”的字段：

`q = clamp((x - P10) / (P90 - P10), 0, 1)`

- `P10/P90` 已改用 Chat 固定的 100 城样本计算，避免极端值支配模型；校准版本为 `cities100-2026-09-11-v1`。
- 校准阈值：温度 4.477/23.418 °C，太阳辐射 2.7325/5.5489 kWh/m²/day，相对湿度 52.322/87.455%，年温差 6.013/27.006 °C；降水与非负海拔先 `log1p`，其变换后阈值分别为 5.8902/7.3653 与 2.8605/7.2020。
- 一旦校准样本锁定，保存 calibration dataset 与版本，不能在每次用户查询时重新计算；新增城市仍使用同一阈值，直到正式发布新校准版本。
- 明确自然上下界的比例字段可直接使用 0–1；偏斜严重的字段先作预先声明的 log 变换。
- `q≤0.5` 时在线性低值和中值响应之间插值；`q>0.5` 时在中值和高值响应之间插值。

### 8.2 城市向量

若字段 `f` 的权重为 `w_f`、响应向量为 `R_f(q_f)`：

`C_i = Σ_f w_f × R_fi(q_f) / 100`

由于字段权重总和与每个响应向量都为 100，理论上 `Σ_i C_i=100`。展示整数时使用最大余数法取整，保证最终五项严格等于 100；计算层保留未取整小数。

### 8.3 缺失值

- 自然字段缺失：使用同气候带、同区域的同类城市中位数插补，并记录 `imputed=true`、同伴组和不确定度。
- 自然字段缺失权重累计超过 20，或温度/水分/地形任一关键分组整体缺失：该城市不得进入公开排名，只能标为“数据不足”。
- 辅助字段缺失：用中性向量 `[20,20,20,20,20]`，不把缺失权重重新分配给自然层，以免不同数据完整度改变 85/15 结构。
- 不允许用编辑者印象补数值。来源冲突时保留两份记录，按来源等级与时间一致性选择，并写审计说明。

### 8.4 城市数据置信度

置信度只表达数据质量，不表达“命理真伪”。建议内部以来源等级、时间窗口完整度、空间覆盖、插补权重和版本新鲜度生成 High/Medium/Low。任何 Low 城市不得显示伪精确到个位小数的排名。

## 9. 个人向量与城市向量的匹配

### 9.1 个人需要向量

优先直接使用 BaZi Engine 输出、总和为 100 的 `base_need_vector=B`。若 MVP 暂时只有主喜与辅助元素，可暂以主喜 55、辅助 30、其余各 5 构造初始向量；这只是接口兼容默认值，最终仍由 BaZi 规则层负责。

为防止低置信度命理解读造成极端推荐，用均衡向量 `U=[20,20,20,20,20]` 收缩：

`N = q_bazi × B + (1-q_bazi) × U`

建议 `q_bazi`：High 0.85、Medium 0.65、Low 0.40。该收缩规则属于现代产品风险控制。

### 9.2 当前大运轻度调整

令 BaZi Engine 给出的有利/不利向量为 `A_i∈[-1,1]`：

`C'_i = normalize(C_i × (1 + 0.10 × A_i))`

大运对每一元素最多作 ±10% 的乘数调整，且调整后重新归一化。BaZi Engine 没有足够置信度时传入全零向量；City Engine 不自行解释大运。

### 9.3 基础匹配指数

`S0 = 100 × cosine_similarity(N, C')`

余弦相似度衡量结构方向，而不是要求城市向量与个人向量拥有相同绝对总量。因五维均非负，结果在 0–100 范围内。前台可显示“匹配度”，但说明页必须写明它是**模型指数，不是统计概率**。

### 9.4 相对方位修正

相对方位必须基于用户明确选择的参考地点，以大圆初始方位角计算；不是城市固有属性：

`S = clamp(S0 + D, 0, 100)`，其中 `D∈[-3,+3]`

默认可先关闭；若启用，东/南/西/北分别仅作为木/火/金/水的轻度传统对应，中心/近距离不强行归土。用户未给参考地点时 `D=0`。

### 9.5 可解释输出

- 显示 Top 城市和整数匹配指数。
- 用 `N_i × C'_i` 最大的 1–2 个元素生成正面理由。
- 如存在明显短板，最多提示 1 个差异元素。
- 分享文案描述“模型中的环境底色与当前需要更接近”，不写“此城一定旺你”。
- 现实筛选结果另列，例如“命理匹配高，但预算条件不符”，不能偷偷改动匹配指数。

## 14. City Engine v0.2：自然原型模型

### 14.1 设计目标与边界

v0.2 用自然原型取代 v0.1 的“单字段直接分配五行”。原型不是气候学分类，也不是对城市文化气质的判断，而是一组可复算的组合特征基函数。一个城市可以同时属于多个原型，最终向量由全部原型权重加权形成。

固定计算链为：

`锁定事实 → 锁定标准化值 → 组合特征 → 12 个原型原始隶属度 → 权重归一化 → 原型五行响应 → 城市向量`

以下信息不进入 v0.2：城市名、国家、地区、历史、大学、经济、行业、企业、美食、建筑、编辑者印象和用户相对方位。现代城市信息只进入未来独立 `City Profile`；现实偏好继续属于筛选层。

### 14.2 基础特征与组合特征

沿用 `cities100-2026-09-11-v1` 已冻结的 `q∈[0,1]`：温度 `t`、日照 `s`、降水 `p`、湿度 `h`、干燥度 `a`、植被 `v`、海拔 `e`、起伏 `r`、大陆性 `c`、沿海性 `o`。`continentality` 已是年温差的版本化转换，因此不再重复加入原始年温差。

地表淡水在 30 km 圆内天然占比较小，使用 `u=clamp(surface_water_fraction/0.12)` 饱和化；WorldCover 海洋像元已经由 Natural Earth 排除，故 `u` 不重复计算海岸。

主要组合特征：

- `wet = clamp(0.38p + 0.27h + 0.20(1-a) + 0.15u)`；同时要求水分输入、空气状态和水分收支，不能由单次高降水决定。
- `dry = clamp(0.42a + 0.23(1-p) + 0.20(1-h) + 0.15(1-v))`；干燥由水分收支、少雨、低湿和稀疏植被共同表达。
- `marine = sqrt(o × (1-c))`；必须兼具临海和低大陆性。
- `inland = sqrt((1-o) × (0.35+0.65c))`；远海与大陆性共同影响，但不把“非沿海”直接等同于干燥。
- `lush = sqrt(v × wet)`；植被与湿润共同出现才形成强生长信号。
- `tri(x,m,d)=clamp(1-|x-m|/d)` 用于温带、中间降水和盆地起伏等非单调响应。

每个原型的原始隶属度使用带权模糊 AND：

`m_k = max(0, exp(Σ_j w_kj × ln(0.025+z_j) / Σ_j w_kj) - 0.025)`

再以 `2.15` 次幂适度锐化并归一化：

`P_k = m_k^2.15 / Σ_h m_h^2.15`

因此每个 `P_k∈[0,1]` 且十二项合计 1。几何聚合要求组合条件共同成立，幂次锐化用于降低所有城市向平均原型收缩；二者都是现代产品设计参数，不是传统术数规则。

### 14.9 初次锁定建议与剩余风险

100 城初次审计曾建议把 `city-elements-v0.2.0-candidate` 锁定为娱乐型 MVP 的自然模型发布候选，因为火与金已有合理代表、土的重复抬升解除、极端环境差异扩大、向量不再过度平均，且全链路没有人工城市修分。第 15 节随后发现高原、盆地、山地和湿土的土响应略偏保守。Chat 已在 D-016 批准最小调整方案 C，第 16 节记录 `city-elements-v0.2.1-scheme-c-candidate` 的正式重算与回归结果。

当前建议把方案 C 候选锁定为娱乐型 MVP 自然模型；正式发布版本命名仍需 Chat 确认。以下风险必须保留：

1. 五行城市模型不存在客观科学金标，所有数值映射仍是现代娱乐产品设计。
2. NASA POWER 年平均和年总量不能识别降水季节分配，地中海式原型可能把 Honolulu 等全年分布不同的城市吸入；需要月度季节性字段时应发布新事实版本，而不是人工改分。
3. 土仅在 2 城成为最高维度。当前样本中这是去除重复计权后的结果，不应为了配额强行抬升；扩城时需继续监测。
4. 12 个原型是重叠基函数，不要求每个都成为某城第一原型；`humid_mountain_coast` 等原型即使常为第二或第三，也能解释组合贡献。
5. L1 适合本轮模型差异审计，但个人向量匹配仍需另行确定标定方法，不能直接把 `100-L1` 当概率或“契合百分比”。
6. 城市自然向量只描述 30 km / 源气候网格下的环境组合，不能替代城市内部社区差异、生活成本、签证、工作或个人天气偏好。

- `dry_continental_steppe` 响应未改；高原土性的增加来自已批准的组合原型响应，而不是重新叠加海拔、干燥和内陆单项。

全部回归闸门通过。T-004 的方法论、事实快照、100 城向量和偏差审计已经达到娱乐型 MVP 所需稳定度，建议把 `city-elements-v0.2.1-scheme-c-candidate` 锁定为当前 City Engine 自然模型；以后只有事实快照、原型公式或响应矩阵发生实质变化时才发布新版本。

### 16.6 Matching Engine 必须继承的接口与约束

City Engine 向 Matching Engine 输出：

```json
{
  "city_id": "",
  "element_order": ["wood", "fire", "earth", "metal", "water"],
  "city_vector": [0, 0, 0, 0, 0],
  "city_vector_raw": [0, 0, 0, 0, 0],
  "dominant_element": "wood|fire|earth|metal|water",
  "dominant_margin": 0,
  "mapping_version": "city-elements-v0.2.1-scheme-c-candidate",
  "source_snapshot_version": "city-facts-2026-09-11-v1",
  "calibration_version": "cities100-2026-09-11-v1",
  "data_confidence": "medium"
}
```

Matching Engine 必须遵守：

1. 固定使用 `[木,火,土,金,水]` 顺序，并把 BaZi、City 和 Matching 三个规则版本同时写入结果；不同版本结果不得静默混用。
2. 匹配读取完整连续向量；`dominant_element` 只用于摘要，不能代替五维计算。低领先差值城市应允许“复合型”解释。
3. 当前大运只轻度调整个人需要向量，不改城市固有向量；相对方位只作独立、可关闭、最多 `±3` 分的用户特定修正。
4. 天气偏好、预算、签证、语言和职业继续属于现实筛选层；`City Profile` 只负责事实差异化解释，均不得回写自然向量。
5. L1 继续用于城市模型回归，不直接转换为 `100-L1` 或客观概率。前台“匹配百分比”必须另行标定，并明确是娱乐型指数。
6. 输出需保留主要贡献元素、冲突或短板、BaZi 置信度、城市数据置信度和完整版本链，确保同一输入可重复得到同一结果。

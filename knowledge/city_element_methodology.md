# 城市五行方法论 v0.1

- 状态：T-004 方法论候选，等待 Chat 审核权重与映射表
- 最后更新：2026-09-10
- 关联决策：D-013
- 适用范围：娱乐型 MVP 的城市五行向量与匹配指数
- 不适用范围：迁居、投资、就业、签证、医疗或其他现实决策

## 1. 结论摘要

MVP 将每个城市表达为固定顺序的五维向量：

`[木, 火, 土, 金, 水]`

五项总和为 100，不给城市贴单一五行标签。推荐初版采用：

- 自然与地理环境层：85%。
- 可核验的现代城市功能辅助层：15%。
- 用户相对方位：不写入城市固有向量，只在最终匹配指数上作最多 `±3` 分的可选修正。
- 现实偏好：天气偏好、预算、签证、语言、职业机会等独立筛选，不进入命理匹配指数。

传统文献只提供五行的高层语义方向；“某毫米降水对应多少水”“金融占多少金”等具体量化关系没有传统金标，均属于现代产品设计。本方案因此要求事实、映射、评分和文案四层分离并分别版本化。

## 2. 设计边界与引擎接口

### 2.1 四层分离

1. **城市事实层**：保存数值、空间范围、年份、发布者、URL、许可和采集日期。
2. **五行映射层**：把事实字段映射为五维响应向量；保存规则版本、理由、反例和测试。
3. **匹配层**：使用个人需要向量、城市向量及轻度大运调整计算娱乐型指数。
4. **现实筛选层**：预算、签证、语言、天气偏好和职业等；独立展示，不改变命理分。

### 2.2 BaZi Engine → City Engine

City Engine 不读取生辰，也不反向修改命理结论。BaZi Engine 应提供：

```json
{
  "element_order": ["wood", "fire", "earth", "metal", "water"],
  "base_need_vector": [0, 0, 0, 0, 0],
  "primary_element": "",
  "secondary_element": "",
  "confidence": "high|medium|low",
  "dayun_adjustment_vector": [0, 0, 0, 0, 0],
  "rule_version": ""
}
```

`dayun_adjustment_vector` 的每项范围为 `[-1, 1]`，表示当前大运对“个人需要”的有利或不利方向。City Engine 不得仅凭大运地支所属五行自行判断吉凶。

## 3. 空间、时间与来源标准

### 3.1 城市空间定义

- 城市锚点使用 GeoNames 的 WGS84 坐标与唯一 ID；保存数据快照日期和许可信息。GeoNames 数据以 CC BY 4.0 提供。[^9]
- 自然环境默认统计锚点周围 **30 km 半径**，以减少行政边界差异造成的不可比性。
- 明确依赖行政区的现代城市功能字段，必须同时保存行政边界版本；不得与 30 km 自然环境统计混称为同一地理范围。
- 沿海距离、河湖邻近度和城市地表水比例是三个不同字段，不能互相替代。

### 3.2 时间基准

- 气候正常值统一使用 **1991–2020** 三十年窗口。
- 生产版优先从 ERA5/ERA5-Land 的温度、降水、辐射、湿度及蒸散相关变量计算一致窗口的指标。ERA5-Land 月平均数据覆盖 1950 年至今、约 0.1° 网格，并采用 CC BY 4.0。[^4]
- 本文件 8 城 demo 使用 NASA POWER Climatology API 的 1991–2020 数据快速验证模型形态；该服务支持自定义气候窗口和多参数请求。[^3]
- 地表覆盖默认使用 ESA WorldCover 2021 v200；其为 10 m、11 类全球地表覆盖产品，许可为 CC BY 4.0。[^5]
- 地形使用 Copernicus DEM GLO-90；水系使用 HydroSHEDS/HydroLAKES；海岸线使用 Natural Earth 1:10m 数据。[^6][^7][^8]

### 3.3 来源优先级

1. 官方或国际科学数据产品，且方法、版本、许可清楚。
2. 城市/国家统计部门的可比指标。
3. 可复核的开放数据集。
4. 编辑策展只可用于文案，不得伪装成城市事实或在无标记情况下进入数值模型。

### 4.1 防止重复计权

- `precipitation`、`humidity`、`aridity` 都描述水分，但反映降水输入、空气状态和水分收支，必须分别保留并设置组权重上限；三项合计固定为 22，不再加入同义“湿润度”。
- `surface_water_score`、`coast_proximity` 与 `continentality` 分别描述本地水体、海岸邻近和气候海洋性，不互相复制。
- `elevation` 和 `ruggedness` 分别描述高度与起伏；平坦高原和低海拔山地应能得到不同结果。

## 5. 传统语义与现代映射的边界

《尚书·洪范》以“水曰润下、火曰炎上、木曰曲直、金曰从革、土爰稼穑”概括五行性质。[^1] 《黄帝内经·素问》进一步建立东方/风/木、南方/热/火，以及寒、暑、燥、湿、风等对应关系。[^2]

本产品只把这些内容作为高层语义锚点：

| 元素 | 传统语义锚点 | 在城市模型中的谨慎转译 |
|---|---|---|
| 木 | 生长、曲直、东方、风 | 植被、生长条件、教育与创新的辅助含义 |
| 火 | 炎热、向上、南方、明亮 | 温度、太阳辐射；活动性只在辅助层体现 |
| 土 | 稼穑、承载、中央、湿土 | 地形、海拔、地表稳定性；不是“所有陆地” |
| 金 | 从革、收敛、西方、燥 | 干燥、强大陆性；金融/制造是现代辅助类比 |
| 水 | 润下、寒、北方 | 水体、湿润、海洋性、低日照/低温倾向 |

以下内容明确属于**现代原创产品设计**，不是传统文献直接给出的结论：字段选择、30 km 半径、1991–2020 窗口、所有权重、百分位阈值、五维响应向量、余弦匹配、置信度收缩、大运 10% 上限和相对方位 `±3` 分。

## 6. 字段到五行的初版响应矩阵

每个事实字段先转成 `q∈[0,1]`，再在低/中/高三个锚点间线性插值。每个锚点自身均按 `[木, 火, 土, 金, 水]` 排列且总和为 100。

| 字段 | 低值响应 | 中值响应 | 高值响应 | 设计理由与防偏差说明 |
|---|---|---|---|---|
| 温度 | `[10,5,15,20,50]` | `[30,20,25,10,15]` | `[20,50,10,5,15]` | 冷偏水、热偏火；中温给生长之木，避免冷热二分法 |
| 日照 | `[15,5,15,15,50]` | `[25,25,25,15,10]` | `[10,60,15,10,5]` | 光热偏火，少日照偏水；单项权重受限 |
| 降水 | `[10,15,35,30,10]` | `[30,10,25,15,20]` | `[35,5,10,5,45]` | 多雨同时支持木与水；少雨不直接等于火 |
| 湿度 | `[10,15,30,35,10]` | `[25,15,25,15,20]` | `[30,5,10,10,45]` | 干燥偏金土，湿润偏水木 |
| 干燥度 | `[30,5,10,10,45]` | `[25,15,25,15,20]` | `[10,25,35,25,5]` | 高值代表干燥；把干热、土与燥金分开承载 |
| 地表水 | `[15,10,35,25,15]` | `[25,10,20,15,30]` | `[25,5,10,5,55]` | 水为主，同时承认水域与植被环境的关联 |
| 植被 | `[5,15,35,30,15]` | `[35,10,25,15,15]` | `[60,5,15,5,15]` | 植被高值主要归木；低值不自动归火 |
| 海拔 | `[25,15,20,20,20]` | `[20,10,40,20,10]` | `[10,5,55,25,5]` | 海拔主要进入土；高海拔辅以金的收敛感 |
| 地形起伏 | `[25,15,25,20,15]` | `[20,10,45,20,5]` | `[15,5,55,20,5]` | 山地承载和形体主要归土 |
| 大陆性 | `[20,15,15,15,35]` | `[25,15,25,20,15]` | `[15,10,30,35,10]` | 海洋性偏水，年温差大的大陆性偏土金 |
| 沿海性 | `[20,10,35,25,10]` | `[25,10,25,15,25]` | `[25,5,10,5,55]` | 临海提高水，但权重仅 6，不能决定全局 |

辅助字段使用强度 `z∈[0,1]` 从中性向量 `U=[20,20,20,20,20]` 向原型插值：

`R_aux(z) = (1-z)U + zA`

| 辅助字段 | 高强度原型 A | 说明 |
|---|---|---|
| 金融/商业服务 | `[5,5,15,60,15]` | 金融归金是现代功能类比，不是城市客观“气质” |
| 制造/物流 | `[5,25,20,45,5]` | 金体现制造与规则，火体现动力，土体现基础设施 |
| ICT/R&D | `[40,40,10,5,5]` | 木代表生长创新、火代表传播速度；避免“科技城市一律火” |
| 教育/创意文化 | `[50,25,15,5,5]` | 学习成长偏木，表达传播偏火；只用可核验指标 |

## 7. 权重建议与选择理由

| 分组 | 字段 | 权重 |
|---|---|---:|
| 热量 | 温度、日照 | 18 |
| 水分 | 降水、湿度、干燥度 | 22 |
| 地表生态 | 地表水、植被 | 20 |
| 地形 | 海拔、地形起伏 | 13 |
| 海陆性 | 大陆性、沿海性 | 12 |
| 现代功能 | 金融、制造物流、ICT/R&D、教育创意 | 15 |
| **合计** |  | **100** |

这样分配是为了让气候、水体、植被与地形共同决定自然底色，任何单一字段都不能让城市“一票归水/火/土”。社会属性的 15% 足以区分自然条件相近的城市，但无法推翻自然层。上述数值是 T-004 的可测试初版，需要 Chat 审核后才能成为正式产品规则。

## 8. 归一化、取整与缺失值

### 8.1 字段归一化

对方向为“数值越大，q 越大”的字段：

`q = clamp((x - P10) / (P90 - P10), 0, 1)`

- `P10/P90` 使用锁定后的首批约 50 城样本计算，避免极端值支配模型。
- 一旦 MVP 城市清单锁定，保存 calibration dataset 与版本，不能在每次用户查询时重新计算。
- 明确自然上下界的比例字段可直接使用 0–1；偏斜严重的字段先作预先声明的 log 变换。
- `q≤0.5` 时在线性低值和中值响应之间插值；`q>0.5` 时在中值和高值响应之间插值。

### 8.2 城市向量

若字段 `f` 的权重为 `w_f`、响应向量为 `R_f(q_f)`：

`C_i = Σ_f w_f × R_fi(q_f) / 100`

由于字段权重总和与每个响应向量都为 100，理论上 `Σ_i C_i=100`。展示整数时使用最大余数法取整，保证最终五项严格等于 100；计算层保留未取整小数。

### 8.3 缺失值

- 自然字段缺失：使用同气候带、同区域的同类城市中位数插补，并记录 `imputed=true`、同伴组和不确定度。
- 自然字段缺失权重累计超过 20，或温度/水分/地形任一关键分组整体缺失：该城市不得进入公开排名，只能标为“数据不足”。
- 辅助字段缺失：用中性向量 `[20,20,20,20,20]`，不把缺失权重重新分配给自然层，以免不同数据完整度改变 85/15 结构。
- 不允许用编辑者印象补数值。来源冲突时保留两份记录，按来源等级与时间一致性选择，并写审计说明。

### 8.4 城市数据置信度

置信度只表达数据质量，不表达“命理真伪”。建议内部以来源等级、时间窗口完整度、空间覆盖、插补权重和版本新鲜度生成 High/Medium/Low。任何 Low 城市不得显示伪精确到个位小数的排名。

## 9. 个人向量与城市向量的匹配

### 9.1 个人需要向量

优先直接使用 BaZi Engine 输出、总和为 100 的 `base_need_vector=B`。若 MVP 暂时只有主喜与辅助元素，可暂以主喜 55、辅助 30、其余各 5 构造初始向量；这只是接口兼容默认值，最终仍由 BaZi 规则层负责。

为防止低置信度命理解读造成极端推荐，用均衡向量 `U=[20,20,20,20,20]` 收缩：

`N = q_bazi × B + (1-q_bazi) × U`

建议 `q_bazi`：High 0.85、Medium 0.65、Low 0.40。该收缩规则属于现代产品风险控制。

### 9.2 当前大运轻度调整

令 BaZi Engine 给出的有利/不利向量为 `A_i∈[-1,1]`：

`C'_i = normalize(C_i × (1 + 0.10 × A_i))`

大运对每一元素最多作 ±10% 的乘数调整，且调整后重新归一化。BaZi Engine 没有足够置信度时传入全零向量；City Engine 不自行解释大运。

### 9.3 基础匹配指数

`S0 = 100 × cosine_similarity(N, C')`

余弦相似度衡量结构方向，而不是要求城市向量与个人向量拥有相同绝对总量。因五维均非负，结果在 0–100 范围内。前台可显示“匹配度”，但说明页必须写明它是**模型指数，不是统计概率**。

### 9.4 相对方位修正

相对方位必须基于用户明确选择的参考地点，以大圆初始方位角计算；不是城市固有属性：

`S = clamp(S0 + D, 0, 100)`，其中 `D∈[-3,+3]`

默认可先关闭；若启用，东/南/西/北分别仅作为木/火/金/水的轻度传统对应，中心/近距离不强行归土。用户未给参考地点时 `D=0`。

### 9.5 可解释输出

- 显示 Top 城市和整数匹配指数。
- 用 `N_i × C'_i` 最大的 1–2 个元素生成正面理由。
- 如存在明显短板，最多提示 1 个差异元素。
- 分享文案描述“模型中的环境底色与当前需要更接近”，不写“此城一定旺你”。
- 现实筛选结果另列，例如“命理匹配高，但预算条件不符”，不能偷偷改动匹配指数。

| 洛杉矶 | `[21,18,25,17,19]` | 土 | 高日照提高火；干燥和起伏让土高于沿海带来的水 |
| 东京 | `[27,13,21,14,25]` | 木 | 湿润、临海和植被共同形成木水结构 |
| 新加坡 | `[28,15,16,12,29]` | 水 | 极湿润、多雨、临海，水最高但仅比木高 1 点 |

结果中没有任何元素超过 29：沿海六城并未全部变成“水城”，只有新加坡以水为最高维；洛杉矶虽临海仍以土为最高；现代功能统一中性，未出现“科技城市一律火”。上海、深圳、伦敦、纽约、东京较相似，反映其自然条件确有共同点；将来只能用有来源的 15% 辅助层作有限区分，不能靠主观 vibe 强行拉开。

## 11. 质量闸门与已知限制

在首批城市发布前，每次模型版本必须通过：

1. 五项均在 0–100 且整数展示总和严格为 100。
2. 单个事实字段缺失或极端时，不应让城市标签完全翻转。
3. 沿海城市样本不得因单一沿海字段全部以水为最高维。
4. 高科技或金融城市不得仅凭辅助层全部变成火或金。
5. 删除全部辅助层后，自然向量应保持可解释；加入辅助层后，任何元素变化应受 15% 总上限约束。
6. 同一输入、同一数据快照与规则版本必须产生完全相同结果。
7. 所有公开解释可追溯到前两大贡献字段，不使用未记录的“城市气场”。

已知限制：五行映射没有可观察的科学金标；权重只能通过稳定性、可解释性、反例和用户体验校准。余弦指数可能整体偏高，MVP 可以保留原始指数并按 50 城固定样本显示排名/分位，但不得通过不透明拉伸把差异包装成概率。

## 12. 版本与审计要求

每条城市记录至少保存：

- `city_id`、坐标、空间统计范围和行政边界版本。
- 每个字段的原始值、单位、时期、来源 URL、发布者、许可、采集日期。
- 缺失/插补标记和同伴组。
- `data_snapshot_version`、`mapping_version`、`calibration_version`。
- 浮点城市向量与总和 100 的展示向量。
- 数据置信度与人工复核状态。

模型更新不得覆盖旧版本；同一用户分享卡应能根据版本号复现。

## 13. 建议 Chat 审核的事项

1. 是否批准自然 85%、现代功能 15%、相对方位最多 `±3` 分的总结构。
2. 是否批准第 6 节的低/中/高响应矩阵进入 v0.1 实测。
3. 是否批准使用固定 50 城样本的 P10/P90 作为 MVP 校准基准。
4. 是否批准余弦相似度、命理置信度收缩和大运每元素最多 ±10% 的匹配框架。
5. 是否批准 GeoNames + ERA5/ERA5-Land + WorldCover + Copernicus DEM + HydroSHEDS + Natural Earth 的来源栈。
6. 后续 50 城在中国、英国、美国、欧洲其他地区、亚洲与大洋洲之间的具体名额；批准前不批量录入。

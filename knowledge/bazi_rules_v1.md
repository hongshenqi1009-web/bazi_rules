# 八字正式规则库 v1

- 状态：已建立首批 Chat 批准的工程与产品规则；确定性算法仍在金标验证
- 最后更新：2026-09-10
- 用途：只保存经 Chat 明确审核批准的正式算法与产品口径

## 审核闸门

任何规则进入本文件前，必须具备：

- 清晰定义和适用范围；
- 可追溯来源及版本；
- 流派/口径差异说明；
- 正例、边界案例和反例；
- 可重复测试；
- Chat 的明确批准记录，并关联 `DECISIONS.md`。

外部代码、书目、Work 研究和实验结论先写入 `github_bazi_audit.md` 或其他候选研究文件。它们不因“看起来合理”或“某个仓库已实现”而自动成为正式规则。

## 已批准规则

### 1. 时间标准化与历法边界

#### BR-001 确定性计算底座

- 决策来源：D-005。
- 适用范围：公历/农历转换、节气时刻、四柱基础值、藏干/十神等确定性原语及大运候选计算。
- 正式规则：以锁定版本的 `6tail/lunar-javascript` 作为候选主底座，只能经内部适配器调用；不得让解释层直接依赖第三方对象或默认参数。
- 角色边界：`zhiji-bazi` 只用于策略、结构、边界案例和判断方法参考；`tianji` 不承担分钟级节气、边界时间或其他核心确定性计算。
- 验证要求：每次版本升级必须运行独立金标；第三方项目之间的一致不能代替独立历法、天文或官方时间证据。
- 未决边界：晚子时默认按同日还是次日尚未决定。
- 已排除：不得采用“日柱不换、时干按次日”的混合兼容模式。

### 2. 四柱计算

四柱具体公式、纪日锚点、立春换年和月柱节界仍在 T-003 验证。当前只批准 BR-001 的底座与封装边界，不把第三方输出直接认定为金标。

### 3. 藏干、十神与五行关系

底层原语可由 BR-001 的候选库提供，但表项、口径和边界仍需独立测试；不得把五行数量直接等同于身强弱。

### 4. 旺衰、格局与调候

- 不写入任何未经验证的数值阈值。
- 研究结果必须区分经典文本、现代解释、工程假设与测试证据。
- 身强弱、格局与调候的具体判定规则仍未批准。

### 5. 喜用神输出结构

#### BR-004 争议结果的结构化表达

- 决策来源：D-008。
- 适用范围：身强弱、格局和喜用神的产品输出。
- 正式规则：输出必须包含主结果、辅助结果、置信度及简短的流派/依据说明。
- 不确定性：证据或验证不足时，必须展示候选与冲突，不得宣称存在唯一正确的喜用神。
- 边界：本规则不批准任何具体数值阈值、权重或自动格局结论。

### 6. 大运计算

#### BR-003 起运时间的存储与展示

- 决策来源：D-007。
- 正式规则：后台保存精确到年月日时的起运时间，并同时保存时区、算法/库版本、口径和计算证据。
- 展示规则：免费版可显示“约几岁起运 / 当前大运”；详细版再展示完整精确时间轴。
- 仍需验证：顺逆、起运折算方法及 `lunar-javascript` 不同 `sect` 的结果尚未形成独立金标。

### 7. 置信度、候选盘与解释边界

#### BR-002 真太阳时候选盘

- 决策来源：D-006。
- 正式规则：真太阳时默认关闭，但后台允许计算。
- 触发条件：若真太阳时导致时柱变化，前台提示用户，并允许高级模式启用。
- 数据要求：保留民用时间、标准化时刻、地点经度、真太阳时候选值、是否跨时辰及计算方法版本。
- 仍需验证：生产均时差算法、经纬度来源、精度与适用年代尚未批准。
